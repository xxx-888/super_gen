SceneGen AI短剧生成平台 — 工作日报
日期：2026-08-14

一、本期完成的核心功能

1. 【H3自部署】MiniMax-H3 Ref2VA 多图参考生视频服务（全新，单卡32G可用）
   - 在单张 RTX 5090 32G 上部署 33B×2 的 H3 Ref2VA：transformer_ref 与 Qwen3VL 文本编码器
     双 bnb nf4 4-bit 量化（覆盖率98.4%，各约17G），按阶段在 内存↔显存 换班调度
   - 绕开官方 ComponentsManager 与 bnb 量化模型的死锁：手动按 pipeline block 分阶段编排
     （文本编码→VAE编码→去噪→解码，各阶段显存峰值 ≤24G）
   - 内置6项兼容补丁（diffusers H3 集成在 torch 2.13+cu132 单卡环境的必要修复）：
     F.conv3d 设备/连续性对齐、混合设备噪声生成器、阶段间组件摘挂、bnb .to() 漏搬
     buffer 补搬、execution_device 钉死 CUDA、DiT 输入对齐 pre-hook
   - FastAPI 服务：提交/轮询/下载/取消 四接口 + Bearer 鉴权 + 看门狗崩溃自启
   - 实测性能：5秒 960×544 带音频视频，standard档约7分钟/条，hd档约12分钟/条
   - 速度/分辨率档位：quality=standard→30步 / hd→49步；resolution≥720p→ffmpeg lanczos
     上采样交付（原生720p在32G显存不可行，注意力显存随像素平方级增长）
   - 参考图编码分辨率自适应分档（1-2张1536 / 3-4张1280 / 5-6张1024），多图不再OOM
   - 帧数档位修复：自动吸附 17n+5 合法档（124~345帧，15秒请求自动落14.4秒，模型硬上限）
   - 日志降噪：fd级截获 C++ 弃用警告与 transformers docstring lint，轮询访问日志过滤，
     任务失败前台打印完整 traceback
   - h3-deploy/ 一体化换机部署方案（service.py / install.sh / start.sh / deploy.md）

2. 【H3 Ref2VA 后端适配器】自定义视频生成模型真实接入
   - 新增 H3Ref2VAAdapter：多图参考收集（首帧→单图→@引用资源图，去重≤9张）multipart 直传
   - 异步提交/轮询协议对齐现有体系：async_poll + poll_result 三态，progress/eta 透传，
     瞬时网络错误自动降级重试，完成自动下载落地本地存储
   - quality→steps、resolution→上采样、时长→帧数 三组参数自动映射
   - 参考绑定语自动注入（<Picture N> 锚定）：官方 ref2va 提示词规范要求显式引用参考图，
     自动补绑定语后角色还原度显著提升
   - 富文本零宽字符（U+200B/U+FEFF）清洗，避免污染提示词
   - 误配防呆：被图片类任务误选中时返回可操作的中文提示

3. 【融合模式适配】provider 白名单与文案修正
   - h3_ref2va 加入 fusion→image_to_video 自动降级白名单（与官方 MiniMax 同款机制，两处）
   - 修正误导文案：「融合生成（文本直接生视频）」→「融合生成（分镜@引用资源图→参考生视频/图，
     按模型自动适配）」
   - 后台模型配置页新增 H3 自部署 provider 预设与超时配置

4. 【提示词扩展】@引用展开改紧凑标签
   - @引用展开从「[角色:名 外观:完整描述]」改为「[角色:名]」紧凑标签
   - 原因：ref2va 模式下外观由参考图承载，文字描述与参考图冲突导致生成结果错乱

5. 【任务取消链路】取消状态全链路回写（修复）
   - 取消任务同步回写关联分镜状态（generating→failed），取消接口与轮询循环双保险
   - 守卫自救：分镜标「生成中」但已无活跃任务（历史残留）时自动复位放行，不再永久卡死
   - 远端取消打通：后端取消→自部署服务释放GPU（排队中立即取消；编码阶段秒级取消；
     去噪中因CUDA不可中断，跑完后丢弃结果）
   - 服务端新增 POST /v1/tasks/{id}/cancel 接口

6. 【排查与实测】参考图有效性 A/B 实验
   - 同提示词/同种子、仅换参考图对照：差异高度集中于画面主体区域（区块差异最大57%、
     最小0.1%，悬殊433倍），构图保持一致——证实参考图生效
   - 定位「还原度弱」三个成因并修复：参考图编码分辨率过低（已提至1536）、提示词缺少
     参考绑定（已自动注入）、零宽字符污染（已清洗）

二、技术改进

   - 单卡量化部署编排：bnb nf4 双大模型按 block 阶段换班，显存/内存双约束下的调度方案
   - fd 级（文件描述符）日志截获：处理绕过 logging/warnings 直写 stdout/stderr 的第三方噪音
   - 服务端任务开局显存复位：上一任务残留 VAE 导致下一任务 OOM 的时序 bug 修复
   - ffmpeg（imageio-ffmpeg 内置二进制）lanczos 上采样流水线，音频轨保留
